# SFT r3 — quality chat dataset

Experiment log for the SFT r3 data build (plan sketch: `HANDOFF_NEXT_AGENT.md`,
"### SFT r3 sketch — quality chat data"). Goal: kill corpus-drift (the
answers-FAIL family in `lab/convo_test.py`), fix arithmetic, and seat the
persona voice. Decode already did its part in the conversational quality pass;
this is the data cure. Builder: `Dataset/11_sft_r3.py`.

## Sources

| # | Source | Origin | Role in the mix |
|---|--------|--------|-----------------|
| 1 | UltraChat 200k (`train_sft`) | fetched once from the public model-hub mirror the lab already uses | anti-drift mass: diverse real multi-turn Q&A, capped ~20M tokens after dedup |
| 2 | OASST2 (`train`, English) | already in the local datasets cache | conversational shape + empathy turns, paths reweighted (r2 used it flat) |
| 3 | GSM8K (`train`) | fetched (small, sketch-mandated) | verbal step-by-step arithmetic; replaces the fake-math salad family |
| 4 | persona synth (local) | `lab/imported/sft_r3/seeds/persona_seeds.jsonl` + builder expansion | persona voice (POI/Gundam/trains/IGBT/cars) |
| 5 | direct-answer pairs (hand-written) | `lab/imported/sft_r3/seeds/direct_pairs.jsonl` + builder variants | the exact failing turn kinds: greeting/small-talk/opinion/show-rec |

Deviations from the sketch, and why:

- **Item 4 substitute.** The sketch's persona self-distill ("1-2k dialogues
  generated by THIS model under shipped decode, kept only if convo_test rubrics
  pass") requires running vk-base itself, which this cycle did not do, so the
  persona set is generated with local text tools instead:
  persona-pack voice facts (from `lab/memories/persona_v1.json`) expanded into
  multi-turn dialogues by a template composer, gated by the convo_test rubric
  family (no_rep / persona-keyword / drift-salad legs). A true self-distill pass
  remains the preferred upgrade when the model can run. The composer yields
  894 kept dialogues (~0.1M tokens) vs the sketch's 1-2k / ~0.5M: expansion is
  template-based, and padding to the target with near-duplicate variants would
  violate the degenerate-repeat hard filter.
- **"2-6-turn paths" for OASST2** read as 2-6 exchanges (4-12 messages), but
  the best-rank English chains in OASST2 top out at 6 messages (hist: 1209
  x 2-msg, 1958 x 4-msg, 80 x 6-msg pre-reweight; no deeper chains exist in
  the tree walk). The extract is therefore 2-6 messages (1-3 exchanges),
  with single-exchange paths kept for the empathy turns the sketch calls for.
  Path lengths are downsampled to <=1.5x the mean per length bucket (the
  "reweighted" instruction) instead of r2's flat walk — that alone cuts the
  4-message bucket from 1958 to 1623.
- **UltraChat dialogue count.** The sketch estimated ~25-30M tokens for all
  200k dialogues; the real corpus is much longer per dialogue, so the explicit
  "cap ~20M tokens after dedup (keep multi-turn only)" binds first. The build
  keeps the token cap (real tokenizer counts, not estimates) and reports the
  dialogue count that cap yields rather than padding to a dialogue target.

## Hard filters (conversation dropped on any hit)

1. **Rejection / refusal / censorship** — refusal-formula openers ("I cannot
   help/assist/comply…", "I must decline", "against my guidelines…",
   "unable to comply", content-filter/upstream-error markers), including
   apology+refusal combos ("I'm sorry, I can't…"). Whole conversation dropped
   if any assistant turn matches. This is the user's hard filter.
2. **Boilerplate AI-disclaimer formula** — sentence-initial "As an AI language
   model, …" family and canned "I don't have personal feelings/opinions"
   disclaimers. Mid-sentence honest identity ("I'm a language model, so I don't
   have an age") is intentionally NOT filtered.
3. **Degenerate repeats** — straight word-line runs, catastrophic unique-word
   ratios, and n-gram density loops. Absolute n-gram caps apply only to short
   texts so long knowledge answers and step-by-step math (which legitimately
   reuse scaffolding) are not over-filtered.
4. **Malformed records** — empty content, control/mojibake characters,
   truncation markers, non-alternating roles, missing user-first /
   assistant-last bounds, absurd length.
5. **Corpus-drift debris on casual turns** — formula/list salad markers
   (equation/compound/enthalpy family) on synthetic casual turns only; real
   knowledge answers in the corpora keep their formulas.
6. **Global exact dedup** — normalized full-conversation hash across all
   sources.

Additional gates: minimum assistant-turn length (20 chars corpora, 12 chars
for the concise direct/persona sets), UltraChat multi-turn-only (>=2
exchanges), GSM8K internal calculator markers (`<<expr=val>>`) stripped and
the `#### N` final line rewritten as "The answer is N.".

hits; GSM8K step text uses a lenient repetition rule (math scaffolding

## Split

Clean train/val split at conversation level, per source, seeded
(`SEED = 20261015`): 95% train / 5% val, min 1 val conversation per source.
Written as `lab/imported/sft_r3/train.jsonl` and `val.jsonl` (messages schema:
`{"source": ..., "messages": [{"role","content"}, ...]}`).

## Training-format output (matches `SFT/01_sft_train.py`)

The previous round's loader (`load_sft_index` / `sft_data_stream`) reads
interleaved `[token, mask]` uint16 `.bin` files listed in an index file of
`name, weight` lines. This build writes exactly that:

- `Dataset/data/sft/sft_r3_<source>.bin` — ChatML turn format identical to
  `Dataset/05_sft_oasst.py` / `06_sft_vesper.py` / `07_sft_openhermes.py` /
  `10_sft_distill.py` (loss mask = 1 on assistant content tokens only;
  2048-position windows as in `06_sft_vesper.py` for multi-turn — the loader
  re-chunks the flat stream at train seq_len; oversized conversations are
  trimmed at exchange boundaries, never mid-turn).
- `Dataset/data/sft/sft_r3_index.txt` — one weighted line per bin.

Each bin packs **train first, then a small pure-EOS pad (mask 0), then val**,
sized so the loader's own positional 95/5 split lands on the clean train/val
conversation boundary. So the run-time val slice is the held-out val set, not a
random tail.

Point the trainer at the r3 mix with:

    VESPER_SFT_DATA=Dataset/data/sft/sft_r3_index.txt

Sampling weights in the index are roughly token-mass proportional with
targeted upweights on the small sets the sketch emphasizes (arithmetic x2,
persona x3, direct-answer x5 vs raw mass) so they are not drowned by the
UltraChat mass. The r2 index is left untouched.

## Validation spot-check

`lab/imported/sft_r3/sample_20.jsonl` — 20 conversations stratified across the
five sources from the train split, for human eyeballing before a training run
(the sketch's training-time bar is conversational: convo_test smoke every 200
steps, accept best only if full convo_test >=8/10 usable with 0 no_rep FAIL
and eval12-grafted >=8/12 under shipped decode defaults).
